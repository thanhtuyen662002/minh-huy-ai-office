# Protected group brain payload format

Issue278 / Draft288. `GroupBrainPayloadCodec` defines private versioned payloads for existing protected request/glossary revisions. It adds no configuration, AI client, SQL effects, registration, Editor permission or provider call.

`group-brain-ai-note-v1` has ten exact fields: version, interpretation_role, note_kind, title_interpretation, problem_interpretation, requested_outcome_interpretation, missing_fields, customer_requested_deadline_text, suggested_relation_hint and evidence. Interpretation role is always source_backed_ai_interpretation. Each evidence item contains only canonical message_id, positive integer revision and an exact quote. No tenant, destination, IT status, assignee, committed deadline or authority can be added. Customer deadline wording must occur literally in an evidence quote; a relation hint stays unverified. Encoding accepts the existing sealed grounded note produced by original-source proposal validation.

`group-brain-glossary-v1` has exactly version, term and explanation. Publication, current same-group scope, membership and extraction policy remain the responsibility of the authorized registry/reader. Payload text cannot enable extraction or establish Editor authority.

Both formats reject decoded duplicate/unknown/missing fields, invalid types, empty or format-only required text, out-of-range fields, malformed Unicode, total UTF8 size above64000 bytes and known secret-policy matches in the entire decoded JSON object. AI notes additionally require1..10 distinct evidence tuples, canonical nonzero message IDs and at most10 distinct missing fields; needs_clarification requires at least one missing field. Exact Unicode, whitespace, quotes and customer deadline wording are preserved. Error and ToString output contain fixed metadata only. Raw Unicode serialization is private storage/context data and must never be inserted into HTML.

Decoding establishes format only. It does not prove that a quote occurs in current original source, an interpretation is true, an IT operator confirmed it, a selection is relevant/complete, token accounting is qualified or future provider/effect release is authorized. The qualified context/store must bind the decoded AI evidence and kind to the exact sealed reader metadata, verify original source and current dependencies, apply policy/budget and fence each release/commit. IT-edited and host-attention formats are not covered and must not be relabelled as AI notes.

The prepared native reader fixture remains opaque synthetic data; this change does not turn that fixture into a production note/model evaluation.38 focused local controls pass without any real model. Existing Gateway real-model qualification remains NOT RUN / UNEVALUATED.
